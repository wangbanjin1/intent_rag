## 五条总原则（所有主题的元结论）

1. **先查 harness 结构，再归因模型能力**。本项目最大的三次收益（v12.1 demo 补头 +3.7pp、v25.2 对象语义 +6.5pp、v26.2b 段去重）全是 harness 侧修复；此前被归因为"模型能力短板"的错误有相当比例是引用解析/状态合并/生命周期管理的结构缺陷假象。
2. **机制收益必须过噪声带门槛**。单次全量 API 波动 ±1.5pp 是系统物理属性（temp=0 也一样）；低于 ±2pp 的"提升"一律双跑验证 + 翻转归因，用机制因果面而非总分判定。**判分口径变化时同理：口径收益（诚实度）与总分差要分开论证**。
3. **生成侧喂信息 > 生成侧讲道理 > 生成后修正**。给模型看它看不到的信息（agent 话术、records[0] 明细、意图状态、预计算日期表）是可靠收益；给模型加规则约束是博弈；让模型自查/重试/投票在本任务上全线失败（靶区结构性太小）。
4. **（v27.0 增补，采纳定案 session 92.74%/turn 93.54%）计算与理解分而治之**：同一问题反复失败时，检查历次尝试是否都在把"计算"塞给模型（后处理改 pred、LLM 改写轮都是变体）——把确定性计算抽出来预计算注入，理解留给模型，可能就是破局点。**注意注入机制的错误是乘性的：一条规则的错误输出会经另一条规则背书放大（v27 run1 −6.8pp 根因），回放必须覆盖高频句式+盯机制桶增量**。

5. **（v28.2/v28.3 增补，d930 定案 94.60%/95.07%）修规则必须同步修其下游消费者 + 跨代数据集当探针**。①extractor 修复放行了证据，下游 prompt 文案仍在说"留空"——修了等于没修（v28.2→v28.3 一轮纯粹为此买单）；工程纪律：任何提取器/规则改动，grep 所有引用其结论的 prompt 段落逐一核对语义一致性。②抑制类规则写成条件式（"已明说→落地；真未定→留空"）而非绝对式，配正反双向测试用例；未定词的"限定对象"判定覆盖紧邻/隔值/后向三种形态。③每换代一个数据集，正则触发器与 harness 防御的真实覆盖面就被重新审计一遍——d930 一代暴露三个潜伏 bug（id 沙箱断裂/Ellipsis 崩溃/未定词误判）+话术代差穿透，换数据集跑全量是成本最低的系统性回归。
