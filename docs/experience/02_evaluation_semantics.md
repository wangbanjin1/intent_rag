# 02 评估口径：假错误的三大来源与修法

> 来源：v17.1（取消计分 +5.83pp）、v20.2（改口豁免 +2.04pp）、v25.1（GT 知二推一 +1.61pp）、v20.1（FMT 标签=0 的证伪）、数据集噪声三路扫描

## 1. 原则：turn 级 GT 的每一步推导都要与模型侧对称

JGA（Joint Goal Accuracy）逐轮比对"截止该轮的累积态"。三个不对称点各吃掉 1.5~6pp：

### 1.1 取消轮（v17.1，+5.83pp，34/34 转正零回退）
- 病：用户取消后 GT 仍记历史态，模型正确移除意图反被判 missed（占 turn 错误 ~15%）。
- 修：取消轮 case GT 记"应为空"，正确移除算命中。定位信号 = 用户 action 含 `Cancel_Request`（全量核验 88/88 可靠）。

### 1.2 改口错误值轮（v20.2，+2.04pp）
- 病："用户说错"场景（T2-3 轮1/T3-2 轮2）GT 按设计记字面错误值，模型正确拒收非法组合（pred 空）反被判错。
- 修：错误值轮 pred 空=命中；pred 非空豁免被更正字段后比其余字段。定位信号 = action 同含 `Negate`+`Correct_Previous_Input`（零误命中）。

### 1.3 GT 不做推导（v25.1，+1.61pp，+11/−0）
- 病：GT 标注只在"字面明说"的轮登记字段；X-2 模板轮2共享时长子句只绑给将被取消的意图（22 个 session）；而模型侧 validator 每轮强制知二推一、GT 最终态三字段必齐——模型在中间轮的正确推导被判错，error_report 还误标成 REA 能力问题。
- 修：turn 级 GT 比对前做与 validator 同规则的知二推一（只补缺失不覆盖）。
- **反向证伪**：关模型推导不可行——判对 turn 的 16.5% 靠 validator 补 duration，全翻错 −12pp。结论：**模型推导是对齐"GT 最终必全"的必要机制，改口径不改模型**。

## 2. 判定假错误的检验顺序

1. **归一化检验**（大小写/空格/数值等价）后发现 GT==pred → FMT 假错误。本项目实测 FMT=0（v20.1），说明 A2 宽松匹配的顾虑在规范化良好的数据集上不成立——但检验本身必须做。
2. **来源检验**：错字段的 GT source_type 是 Record/Memory → 先怀疑画像指代场景的设计（话语本不复述值），不是模型错。
3. **时序检验**：错字段在本轮 GT 无更新（值是早前轮沿用）→ CTX 状态沿用问题，不是本轮理解问题。
4. **标注缺陷检验**：同值同名字段在**将被取消的兄弟意图**上登记更早 → 数据生成器的 evidence binding 缺陷（X-2 共享子句 22 session）。修法优先评估侧口径（gt_derive 覆盖），数据修补可选。

## 3. 噪声剔除

- find_noise.py 客观规则（时间内部矛盾/明说时长不符/画质映射矛盾/record 选择规则）：d5 检出 13 条，7 条在 test → 剔除口径 322。
- 噪声样本单独区块展示（不进统计），record 选取对照（✗GT错选/✓应取）供数据修订。
- 三路扫描（v6.0 后的 0 噪声结论 + v19 重扫 13 条）说明：**噪声扫描要随数据集版本重跑**，规则 R5（record 选择）依赖"生成器与评估顺序一致"这种易变前提。

## 4. 错误归因面板的设计

- 一级桶按"错在哪"（漏意图/record/时间/应用服务/值），二级标签按"为什么错"（FMT/SR/CU/COR/PER/REA/CTX/XFER/INT/GEN，参照 ESF-Bench）——正交两个维度比单维分类的修补指向性强得多。
- 实测分布演化的诊断价值：PER 52>REA 39 说明能力短板（v20.1）；INT 桶 21 例 key 错位（v25.2 前夜）说明结构缺陷——**桶占比突变就是下一个版本的开工令**。
- HTML 报告必备件：turn/session 双视图切换、每意图 7 字段最终态对照、状态机对照、GT 推算值打标、key 错位标注、数据集原始信息折叠块、逐轮状态演进（含继承）。

## 增补（v26.3，2026-09-15）：dict 键唯一假设是第四类假错误来源

本册前三类假错误（GT 字面登记 vs 模型推导错位、取消轮历史态、改口错误值）都发生在"单意图对单意图"的比对内部；v26.3 发现第四类：**比对结构本身的键不唯一**。intent_key=app/svc 时，GT 同 key 双意图与 pred dict 相互塌缩——塌缩恰好相等产生**假阴性**（错判为对，且跨 run 稳定，比随机波动更具欺骗性），塌缩不等产生**假阳性错**（模型输出全对仍判错）。d6 实测 6/234 session 中招。
**判别特征**：这类错误在 error html 上的形态是"turn 级明细与 session 判定矛盾"（逐轮全对但 session 错，或反之）——凡出现这种矛盾，先查比对结构的键唯一性，再查模型。
**修复原则**：GT 侧实例锚点优先用数据集自带的主键（intent_id），不要自己造编号；pred 侧实例编号必须与 GT 侧同序（含 cancelled 占号），否则修一个塌缩引入一个错位。
