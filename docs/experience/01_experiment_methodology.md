# 01 实验方法论：怎么让结论可信

> 来源：v14/v15（API 波动实测）、v17.1/v20.2/v25.1（口径三改）、v23（GT 不变性门控）、v24.5（oracle 门控）、v26 系列（含 bug 采样污染统计的教训）

## 1. temp=0 不是确定性

- temp=0 只关闭客户端采样随机性（贪心解码）。服务端 GPU 并行归约的浮点非结合性、MoE 路由抖动、batch 调度差异，都会在"两个候选 token 概率差 < 数值噪声"时随机裁决。
- 实测：qwen-plus 全量 322 session，单跑间波动 **±1.5pp**（v14: 重跑 241→246；v23: 19 处模型侧差异 0 处可由规则解释）。
- 推论：**任何单跑结论都必须默认携带 ±1.5pp 置信区间**；"<2pp 的提升"不可作为采纳依据。
- 工程建议：请求里传 `seed`（尽力而为，可降频不除根）；更重要的是双跑取均值 + 翻转归因。

## 2. 双跑纪律与翻转归因

- 每个候选版本双跑；比较用均值，判定用**翻转归因**而非总分：
  - 获救 = 新对旧错；回退 = 旧对新错；
  - 对每个翻转 case 逐个核验 llm_raw，分类为"机制因果"还是"运行波动"；
  - **双跑一致翻转集合**才是机制的因果面（v24.1: 获救 25/回退 9、触发∩获救=18 强因果 → 采纳）。
- 稳对口径（双跑都对的数量/独占集）比均值更抗噪，适合判定"真实能力差异"。

## 3. 实验卫生（血泪教训）

- **含 bug 的采样必须从统计中剔除**（v26.2 教训）：段覆盖 bug 的一次跑混入均值/多数票，两次把结论算反（"v26 均值虚高"/"稳对率反输"），被用户质疑后剔除才反转。发现 bug 后先修 bug 重跑，再用干净数据重算所有统计。
- **消融必须单变量**（v22.0 教训）：合并实验（③+④ 一起改）打平时无法归因，拆因才发现 ③ 净有害。多改动合并跑一次"省时间"，归因时加倍还回来。
- **上线前先离线扫描触发器**（v25.0 初版教训）：字面值比对检测器初版误报率 83%（88/106），若直接跑全量就是净负回退重演。触发类机制的纪律：离线扫描触发集合 → 人工核验全部触发 → 再上全量。
- **GT 不变性门控**（v23 教训）：任何触碰数据/规则的工具，先回归验证对 GT 零改动（3388/3388），再谈对预测的作用。

## 4. 口径变更管理

- 评估口径修正（取消计分 v17.1 +5.8pp、改口豁免 v20.2 +2.0pp、GT 知二推一 v25.1 +1.6pp）要：①默认开+CLI 回退开关；②summary 落盘口径标记；③离线复算工具（对旧 eval 重算，不重跑模型）；④CHANGELOG 记录"跨口径比较注意"。
- 口径叠加后（累计 +9.4pp），**跨版本比较 turn 数字必须同口径**，报告里用 † 标注。

## 5. 门控式推进（先算上限再投入）

对任何新机制方向，先构造 oracle/上限测量，低于噪声带直接关闭路线，不写代码：
- 采样路线：v24.1 双跑模拟完美选择器，oracle pass@2 = +1.63pp ≤ 3pp → BoN/投票/verifier 整体关闭（省下全部开发）。
- 反思路线：离线触发扫描得真靶区 4 turn（+0.6pp）→ 不用跑就知判负。
- 本项目被门控关掉的方向：采样/投票/verifier、反思/自纠、时间后处理规则（两模型档封顶）。省下的投入全部转给了生成侧（v24.1 +4.97pp）。

## 6. 消融开关的设计模式

- 每个机制一个独立 config 开关（`xxx_rule.enabled`），默认关，消融可单独回退；
- 机制进报告的义务**不以开关状态为条件**——哪怕最终默认关（record_selector、conflict_check、time_rules），其实验、数据、结论也必须进 CHANGELOG/method（本项目的规则：门控方法全部入报告）；
- 旁路机制（status_tracking）先验证"零副作用"再谈收益（JGA 与基线打平的旁路实证）。

## 7. v26.3 增补：修复迭代期的实验纪律（2026-09-15）

- **架构级改造的首轮全量必然暴露新路径 bug，预算 3~5 轮**。multi_instance_key 首轮 88.03% 看似正常，实际四条 key 路径里三条带病（跨轮断裂/改名自冲突/空段自我吞并），靠五轮全量+翻转归因逐个揪出。**不要用首轮结果下"机制无效"或"机制有效"的结论**——首轮数字衡量的是"实现质量"不是"机制价值"。
- **修复的次生 bug 比原始 bug 破坏力大**（run2 75.64%，−12pp）：为修 A 引入的判定逻辑在"目标=自己"的退化场景反噬。对策=每轮修复配全场景离线回归（见 03 §6.3），且全量跑出错时**先怀疑自己的修复而不是模型**。
- **判分口径变化后，数字与历史不可直接比较**：mi_on 把塌缩假阴性消除（判分变严），session 从 88.46% "掉"到 88.03% 不是回退——同期 dup-key 6/6 从假对/全错变为干净判对。**口径切换的收益要用"暴露了什么真错误"来论证，不能用总分差**。
- 触发器大小写要兜住（S-000220 型漏检）：模型复述规则名时可能改大小写/加连字符（"Pending-App Rule"），触发痕迹检测用 `lower()` 匹配，否则归因时会漏掉机制致错的案例。
