## 族 A：生成范式（Text-to-Python 沙箱）

**做了什么**：B1 RefPyDST 范式——LLM 每轮输出 Python 程序（`state.xxx = ...` + find_* 桩），沙箱执行得 Δy，validator 合并校验。
**评价**：✅ **全项目的正确地基**。相比直接 JSON 输出的优势：①coreference 用变量引用自然表达（`state.rtt`）；②知二推一在代码里可执行可验证；③格式错误可被 PAR 校验捕获重采样。
**边界**：模型必须很强地遵循代码格式（v12.0 缺头灾难）；沙箱执行失败 delta 静默为空（错误被吞，反思回路因此没靶区）。
**给同类项目的建议**：结构化状态跟踪任务优先考虑"代码即输出"范式——可执行性给了你免费的校验器和确定性合并语义。

## 族 B：检索增强（demo 检索 + MMR）

**做了什么**：train case 建 embedding 库，`prev_state||utterance` 查询，MMR 多样性选 4 正 2 负例入 prompt。
**评价**：✅ 最大单一基建收益（+8pp），但 demo 是双刃剑——教格式也教坏习惯（v12.0 缺头、v21.0 序数都是 demo 教出来的）。
**关键细节**：①build_casebank 必须显式数据集路径（v16 误建 376 条）；②协议改动 → demo 重渲染 → embed cache 重建，三件套一起动；③负例（invalid case）同样有价值（schema 约束教育）。

## 族 C：Prompt 信息注入（喂信息派）

**做了什么**：agent 上轮回复（v13.1）、状态快照（v16.0）、records[0] 明细（v24.1）、消歧候选对照表（v24.3）、**时间预计算注入（v27.0 日期表+明说时间预解析+四条口径规则）**。
**评价**：✅ **性价比之王**。四次大收益全是"把模型看不到的信息给它"：+3.30/+1.43/+4.97/**+4.71pp**。
**根因**：多轮对话里信息天然不对称——agent 话术、画像、历史状态都在上下文里但模型每轮只看 user 话语；时间的日期算术则连话语里的信息模型都"看得到算不对"（分词割裂，v27 论文依据）——预计算结果注入比预解析原文注入更进一步。
**边界**：长度税（每加一段都检查非目标类回归；v27 用散文段压缩对冲成净 −840 字符）；**注入机制的错误是乘性的**——初版提取器把"晚上7点到8点半"的终点解析成 AM，矛盾规则又指示模型照抄，规则间互相背书放大（run1 −6.8pp 根因）；信息型注入对弱模型收益骤减（32b 上 status_prompt 只 +0.71pp）。**详见 [11_time_rules.md](11_time_rules.md)**。

## 族 D：规则约束注入（讲道理派）

**做了什么**：消歧轮规则（v21.1）、改口轮规则（v22.1）、record 不超前（v22.0③ 回退）、纠正 demo（v12.1）。
**评价**：⚖️ **有效但脆弱，必须触发式**。采纳的三个都是"触发条件命中才注入"，全 always-on 的都翻车（v22.0③ 确认轮丢意图、v8.0-a 全局扰动）。
**两条铁律**：①规则必须与模型可见信息结构对齐（v21.0 说"按 agent 话术顺序"但模型只看到 records 列表 → 净负；v24.3 把顺序显式渲染成对照表才闭环）；②约束识别粒度在真实错误样本上逐例调（v24.0 的 `_extract_record_filters` 把新意图目标 app 当筛选条件 → 零覆盖）。
**收益天花板**：约束型规则的收益天花板比信息型低一个量级（+0.3~0.6pp vs +3~5pp）——规则只能防错，信息才能启用新能力。

## 族 E：生成前强制推理（PAR 派）

**做了什么**：强制 `# summary`（v2.0，S3-DST）、选择链 summary（v11）、身份判定行（v26.2）。
**评价**：✅ **三次成功，同一原理**：逼模型在行动前先枚举可用选项并写出理由。选择链 +2.87pp（record 选择）、身份判定救 new 重建（S-000040/845/935/325）。
**代价**：prompt 税（每段 +1 行）+ 形式遵从风险（模型会写正确理由得出错误结论——判定行不是逻辑约束，需要 harness 去重兜底）。
**适用判据**：错误样本中"模型没看选项就行动"比例高 → 值得；纯值波动 → 加行只是加税。

## 族 F：后处理/二次干预（选值派）

**做了什么**：规则补全（v5.0）、加权投票（v9.0）、重注入二次 LLM 选择（v10.0）、record_restraint（v22.0③）。
**评价**：↩️ **四连败，整体封死**。根因：validate 之后二次干预，"只补缺失"保护不住重新 validate 的连带破坏（时间字段/intent_key 连锁坏）；翻转值是多稳定吸引子竞争（profile 习惯值 vs records[0] vs records[1]），投票选出的是贪婪已选的吸引子。
**给同类项目**：模型没输出对的问题在生成侧解决（demo/prompt/喂信息）；输出后的修修补补是在错误的地基上贴瓷砖。

## 族 G：反思/自纠/校验驱动（回头看派）

**做了什么**：validator 信号分层 + 话语明说值冲突检测 + bounded 重生成（v25.0，形态纪律拉满：0 误报/逐意图采纳/默认关）。
**评价**：↩️ **双跑一致净负**。三次同构证伪（§6 设计核验/v23.2 回放/v25.0 全量）。
**根因（可迁移）**：①invalid≠错误（大部分是正常未收齐）；②执行错误被沙箱吞；③时间错自洽但推错，字面比对无矛盾可抓；④话语明说值被选择疑问句/上下界/串扰污染；⑤**模型对"校验器说你错"9/10 拒绝改动**。
**什么条件下值得做**：有强结构校验（SQL 可执行/编译/测试通过）、错误是发散型、oracle 门控 > 噪声带×1.5、采纳率实测 >20%。本项目的校验信号最终复用于身份判定 PAR（生成前）和 err_report 归因——**信号用于生成前决策有效，用于生成后纠错无效**。

## 族 H：采样与多路（投票派）

**做了什么**：v24.1 双跑模拟完美选择器，oracle pass@2 上限测量。
**评价**：↩️ **门控关闭（+1.63pp ≤ 3pp 门槛）**。定量：翻转 turn 即 p≈0.5 边缘集，N 取多命中 f(p)=3p²−2p³，净增益 0~0.6pp，需 3~5× 成本。
**教训**：先测 oracle 上限再写代码；唯一能突破的形态是 BoN+独立训练 verifier（新训练投入，非 prompt 技巧），需单独立项。

## 族 I′：harness 确定性解析 + 安全回退（candidate_map 派）

**做了什么**：v24.3/v24.4 harness 解析 agent 话术的候选顺序 → 注入"第N条=记录字段明细"对照表；解析失败回退纯文字规则。
**评价**：✅ **d5 上打平（−0.62pp 噪声带内）、d6 上转正（+2.99pp，T3-3 0.30→0.50）**——同一机制在两个数据集上表现不同，因为 D6 新渲染的消歧话术更难（两套顺序对齐负担更重）。**跨数据集表现差异本身就是泛化性诊断信号**。
**关键设计**：解析器对 D6 新话术变体（日期式枚举"7月18日还是7月11日"）覆盖率仅 45%，但失败**安全回退**纯文字规则（不注入错误对照表）——机制可以弱，回退必须安全。
**给同类项目**：harness 确定性解析类机制的上限 = 话术格式覆盖率；覆盖率不足时回退路径的质量决定机制下限。"打平"的机制不要急着回退，换数据分布再验。

## 族 I：协议化/身份表示（id 协议派）

**做了什么**：稳定意图 id 与内容 key 解耦（v26.0 裸协议）→ 归并校验/cancel 名字化/身份判定强制化/段去重四补丁（v26.1→v26.2b）。
**评价**：✅ **最终采纳，但形态出乎设计初衷**——不是"协议替代 harness"，而是"协议 + harness 兜底"三层混合。裸协议 −3.11pp 证明：模型可靠承担显式指派（改口/多意图），承担不了推断指派（补全型共指）；遵从率 100% ≠ 语义正确。
**方法论收获**：每轮"单跑+翻转归因→根因→补丁"的迭代节奏，四轮从 −3pp 走到 +1.4pp；含 bug 采样剔除的实验卫生教训。

### 族 I+：同 key 多意图实例化（v26.3-p3，族 I 的续章）

**做了什么**：id 协议把"身份"解耦了，但"内容 key"仍是 app/svc——同 key 双意图在 GT/pred/状态机/报告四处 dict 塌缩。v26.3-p3 引入实例后缀 `app/svc#N`（harness 内部，模型不可见），GT 按 intent_id 锚定。
**评价**：✅ 采纳。session 总分与 mi_off 持平（88.03% vs 88.46%），但**判分诚实度质变**：6 个 dup-key session 从假对/全错变为干净判对，塌缩掩盖的真错误（S-000046 画质错）暴露。五跑迭代修四条 key 路径 bug——架构改造的隐性成本主要在"所有从内容推导 key 的旧代码路径"，不在新机制本身。
**方法论收获**：①dict 键唯一是隐含假设，换数据分布必须显式验证；②判分变严的收益要用"暴露了什么"论证，不能用总分差；③架构改造首轮全量必然暴露新路径 bug，预算 3~5 轮，每轮修复配全场景回归。

## 族 J：评估口径修正（对称性派）

**做了什么**：取消计分（v17.1）、改口豁免（v20.2）、GT 知二推一（v25.1）。
**评价**：✅ **turn 累计 +9.4pp，零模型成本**。统一原则：GT 的每步"加工"只要模型侧对称做了，评估侧必须同步；否则模型越对齐 GT 最终态越被中间轮惩罚。
**方法**：默认开+CLI 回退+summary 落盘口径标记+离线复算工具（不重跑模型）+跨口径换算表。

## 族 K：数据集/映射表工程

**做了什么**：画质映射表从 train source_ref 还原（v20.0 +2.17pp）、噪声扫描 R1–R5（13 条剔除）、X-2 标注缺陷甄别（22 session）、三路 GT 话语出处扫描。
**评价**：✅ **低成本高确定性**。映射表类错误是"模型查表遵从度"问题——表补全后间接受益超直接覆盖。数据侧发现的每一类缺陷都要走"证伪评估代码→扫描全量→反例甄别→三性质分类（缺陷/设计口径/模型错）"流程。

## 族 L：模型选择 + 弱模型适配

**做了什么**：plus / 32b / 235B / qwen3.8-27b 四档对照（v14/v17/v18/v23.3 + v26.2c 同配置对照）。
**评价**：📊 两个结论：
1. **模型锚点**：qwen-plus > qwen3.8-27b > 235B 旗舰 > 32b。指令特化模型不能按参数量对标——plus ≈"新一代 27B 指令特化档"；状态快照等注入收益随模型能力增长（v16：plus +1.43pp vs 32b +0.71pp）。
2. **弱模型适配红利与模型强度反序**（v26.2c）：沙箱逐行容错（单行 coreference 失败跳过该行，保已赋值）+"只写变化字段" prompt 两项改造，qwen3.8-27b +11.18pp、235B +20.11pp、32b +12.11pp——**最弱的模型涨最多**。根因：弱模型"过度沿用"（全字段 state.x=state.x，引用 prev 不存在的槽位→整段 delta 丢），容错把"一处引用失败=整段报废"降级为"该字段缺省沿用"；强模型（plus）最小 delta 习惯天然无此问题。
**给同类项目**：①换模型前先跑错误结构分析；②"弱模型在强模型 harness 下暴露的崩溃模式"是适配金矿（完整解剖见 [10_weak_model_adaptation.md](10_weak_model_adaptation.md)）——强模型的规范习惯会掩盖 harness 防御缺口（plus 遵从 100% 掩盖非标头崩溃、掩盖过度沿用），拿一个弱模型跑一遍冒烟是低成本的风险扫描；③写法容错（逐行）+ 写法规范（prompt 约束）双管齐下，收益可平替一代模型差距。

## 族 M：可视化/归因工具（error_report 派）

**做了什么**：错误归类 HTML（v3.1 起）→ 二级标签（v20.1）→ 双视图+状态演进+推算标记+key 错位标注（v25.1/v26 系列）。
**评价**：✅ **不是附属品，是发现引擎**。本项目三次大转向（PER 桶占比、INT 桶 key 错位、X-2 duration 假错误）全部来自报告深挖而非总分变化。"桶占比突变 = 下一个版本的开工令"。
**必备件**：逐轮模型实时输出、GT 来源列、数据集原始信息折叠块、双视图隔离、推算值/错位标注（防误读）。

## 元结论：方法选择的决策树

```
发现错误桶 → 先分类(标注缺陷/设计口径/harness 缺陷/模型能力)
  ├─ 标注缺陷/口径问题 → 修数据或评估口径（零模型成本，优先）
  ├─ harness 缺陷（引用/合并/生命周期）→ 修 harness（高确定性）
  ├─ 信息不对称 → 喂信息（性价比最高）
  ├─ 需要确定性计算（日期算术/格式转换）→ 规则预计算+注入结论（v27.0，+4.71pp）
  ├─ 模型不知道"怎么选/用哪个" → PAR 强制推理 + demo 对齐
  ├─ 模型知道但偶尔违反 → 触发式规则约束（预期收益 <1pp）
  └─ 真能力短板 → 换模型/训练/接受上限
反向路线（后处理/反思/投票）→ 先跑 oracle 门控，低于噪声带×1.5 直接关闭
```

每族方法的收益/成本/风险不是普适常数——**取决于错误结构**。本项目的全部方法学投资最终都指向一件事：把"错误在哪、为什么"搞清楚，方法选择就变成了查表。
