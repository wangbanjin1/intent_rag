# 08 状态机与意图生命周期

> 来源：v13.0（状态机旁路上线）、v13.1（agent_context 破零）、intent_status.py、T2-6/T3-1 模板实证

## 1. 旁路状态机：零风险的第三口径

- 状态机（Collecting/Ready/Confirmed/Cancelled）纯旁路实现：不改 prev_state 透传、不改 validator、不改 JGA 判定——先实证零副作用（JGA 与基线打平），再谈状态口径收益。
- 价值：①第三评估口径（78.74% 基线，分状态画像：Cancelled 97.4% 最好、Collecting 46.1% 最弱）；②错误归因更细（Collecting→Ready 混淆直接指向槽位识别）；③对部署方是免费交付（对话管理需要状态）。
- 设计模式：**任何新评估维度都先做旁路**——不碰主流程就没有回归风险，拿一段时间的双口径数据后再决定是否让状态影响行为。

## 2. 状态推导用确定性规则，不用模型

- Affirm 识别：is_affirm 规则召回 117/117、误报 0——确认场景的话语模式高度收敛（"对的/没问题/是的"），规则完胜模型判断，且零成本。
- Ready 判定 = 五槽齐：与 schema 的 required 槽位对齐，Ack 轮 912 例全五槽齐验证了口径自洽。
- Cancelled = Cancel_Request action 定位：88/88 可靠。
- **迁移经验：状态转移里所有"话语模式收敛"的转移（确认/取消/拒绝）都用规则；只有"信息收集程度"需要槽位判断。**

## 3. 已知边界（诚实清单的价值）

- record 消歧的 Collecting 判定覆盖 62%："就按那条来"类话语无犹豫词，歧义在画像候选数>1，需要画像信息才能判——**sanity 上限 96.28% 与实际 78.74% 的差距要能逐项解释**，否则状态机不可信。
- 模型超前补齐 vs 剧本口径的张力：模型五槽齐判 Ready、GT 按剧本 agent 还在 Request_Slot 判 Collecting——这是**口径固有张力**，要在文档里明示"非纯错误"。
- 域外/rejected 意图不进状态机（与 JGA 口径一致）——口径对齐比覆盖全面重要。

## 4. 意图生命周期管理（与引用解析联动）

- 取消 = 从 session_out/prev_states 移除 + 状态记 Cancelled；v25.2 后归并/改名（consumed key）与取消同路处理——**生命周期事件（创建/更新/改名/取消/合并）要有统一的退役机制**，否则幻影意图残留。
- Confirmed 的确认对象：当前数据 Affirm 全部单意图；多意图确认需要显式确认对象标注——数据扩充前先把口径边界写清楚。

## 5. 状态快照反哺生成

status_prompt（状态快照进 prompt）+1.43pp 且强模型更受益：**状态机的价值不止评估——把推导出的状态喂回 prompt，模型对"哪些槽已收齐/哪些意图待确认"有显式感知，沿用/补全更稳**（幻觉意图减少）。旁路状态机的终局往往是双向的。

## 增补（v26.3，2026-09-15）：同头双意图的取消定位与状态机键

- 取消定位优先级实证：**id 直达（模型写 `# cancel: I1`）> 话语时段文本匹配 > 序数对齐 agent 话术枚举序**。prompt 只需一句"同类多份保障之一写 id"就能让模型走对路径（话语本身常带时段/序数线索，模型在身份判定行里会自己写明对应关系）。
- 状态机的键与 JGA 的键必须同构：GT 状态轨迹与 pred 状态轨迹都按 intent_key 索引时，同 key 双意图同样互相覆盖——实例化改造时**状态机两侧要同步换键**，只改 JGA 侧会让状态机口径静默失真。
- 空赋值沿用段（"保留第二份，无修改"）是取消场景的高危路径：模型合法地不写任何字段，harness 若把"从合并态推导的 key"当新 key 处理会产生伪改名，把沿用意图错误退役。
