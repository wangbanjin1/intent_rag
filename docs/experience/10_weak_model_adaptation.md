# 10 弱模型适配：一次"强模型掩盖缺陷"的完整解剖

> 实验：2026-09-08~09，qwen3.8-27b 首测（v26.2b 配置）→ 三层改造 → v2 复测 + 四模型对照。
> 这是本项目方法论上最重要的一次实验之一：它不是"换了个模型跑了分"，而是**用弱模型当探针，挖出了强模型的规范习惯长期掩盖的三类 harness 防御缺口**。

## 1. 实验背景与数据全景

动机：测量新一代 27B 模型（qwen3.8-27b）在最新 v26.2b 配置（id 协议+归并+身份判定+段去重）下的能力。

| 阶段 | 模型 | session | turn | 状态机 |
|---|---|---|---|---|
| 首测 v1（无容错） | qwen3.8-27b | 77.95% | 84.23% | 80.36% |
| **v2（三层改造后，双跑）** | qwen3.8-27b | **89.91% (89.13/90.68)** | **90.29%** | 85.13% |
| 对照 | qwen-plus（双跑） | 88.67% | 88.83% | 85.73% |
| 同配置对照 | qwen3-235b | 82.61% | 83.65% | 83.38% |
| 同配置对照 | qwen3-32b | 73.29% | 77.37% | 80.06% |

**三层改造总收益：qwen3.8-27b +11.96pp，双跑坐实反超 plus（稳对 282 vs 275 净 +7，当前单模型最高分）**；改造红利与模型强度反序（235B +20.11pp、32b +12.11pp、q38 +11.96pp，plus 0——它本来就不需要）。

## 2. 根因解剖：一份从未写下的契约

沙箱与模型之间有个隐式契约：**程序里每句 `state.xxx` 引用的槽位，prev 里必须真的存在**。这份契约从未写进 prompt，也从未在沙箱里防御——因为 qwen-plus 从不违反它。

qwen3.8-27b 的"过度沿用"写法（真实输出，S-000006 轮2，prev 只有 app/svc/rtt）：

```python
# 身份判定: 更新已有意图 I1(Telegram/视频通话)     ← 判定正确
# intent: I1
state.application_name = state.application_name    # 冗余但无害
state.service_name = state.service_name            # 冗余但无害
state.resolution = "540p"                          # ← 这句是对的!
state.rtt = state.rtt                              # 冗余但无害
state.timestamp = find_timestamp(start=state.start_timestamp, ...)
                                # ↑ prev 里没有 start_timestamp → AttributeError
```

**沙箱按整段执行：一行崩 → 整段 delta 丢弃 → 连写对的 resolution 一起没了。**

为什么弱模型会这样写？两个动机叠加：①怕"不写就丢了"（对沿用语义不信任，写全字段求保险）；②模仿训练语料里"完整覆盖式"的更新程序（demo 里多为首次填写场景，全字段写齐是合理的；多轮部分更新场景 demo 覆盖不足）。plus 不这样写是因为它对"未写=沿用"的语义有内化的信任——这本身是模型能力的一部分，但**把这份能力当成系统前提，就是隐式契约**。

## 3. 三层改造（对应三层责任）

### 3.1 沙箱逐行容错（harness 层，治"崩溃放大"）

`execute_program(line_tolerant=True, 默认开)`：执行单位从整段降到行，单行异常跳过、已成功赋值保留：

```python
for ln in code.splitlines():
    try: exec(ln, glob, loc)
    except Exception: continue      # 该行缺省 = 字段沿用 prev, 正是模型想要的语义
```

- 语义保持的关键：state 对象跨行共享，行间"依赖"只有 state 自身累积——与整段 exec 等价，除了失败行降级为缺省沿用。
- 代价：放弃原子性（理论上半途而废的段会留下部分 delta）。本项目接受此代价，因为 ①部分 delta 永远好过空 delta（validator/prev 沿用会兜住缺字段）；②崩的行本来就是模型写错的。
- **对强模型零影响**（实证：plus 3 靶向 session 回归冒烟与双跑一致）——plus 的程序没有会崩的行。

### 3.2 "只写变化字段" prompt 约束（模型层，治"写法习惯"）

id 协议 TASK 块新增：

> 只写【发生变化的字段】的赋值；未变化的字段不要写 `state.xxx = state.xxx` 沿用（未写的字段自动沿用该意图当前状态；写了反而可能因引用不存在的槽位而出错）

设计要点：①**明说"不写=沿用"**——弱模型写全字段的动机是不信任沿用语义，把语义讲透比单纯禁令有效；②**明说写了有害**——给出因果而不是权威；③与 3.1 构成双层防御（prompt 减少坏写法，容错兜住漏网）。

### 3.3 非标头防御丢弃（harness 层，治"格式边缘崩溃"）

qwen3.8 会写 `# intent: I1：`（全角冒号）等变体头 → 解析为"非 id 非 new"→ 落"更新已有意图"分支 → `idbook.key_of` 查不到 → cur_key=None → 段内又没写字段 → `results[None]` → **评估进程崩溃**（不是判错，是跑不下去）。
修复：该分支 k 为空时丢弃该段。plus 从不写这种头（遵从 729/729）——**强模型的遵从性把防御缺口藏了三轮**。

## 4. 元结论（可迁移）

### 4.1 强模型的规范习惯会掩盖 harness 防御缺口

这是本次实验最深的教训。plus 的三个"好习惯"——遵从协议格式、最小 delta、只写存在的槽位——每一个都在替 harness 挡住一类它本该自己防御的输入。**拿一个弱模型在强模型调好的系统上跑冒烟，是发现这类缺口成本最低的手段**：qwen3.8 一轮 8-session 冒烟（崩溃+4 失败）暴露的问题比 plus 双跑 644 个 session 都多。

反过来说：**在强模型上调出来的系统，对弱模型的实际兼容性是未知的**——"在 plus 上 88 分"不等于"系统好"，可能只等于"系统与 plus 的习惯刚好咬合"。

### 4.2 弱模型适配红利与模型强度反序

四模型对照：235B +20.11pp > 32b +12.11pp ≈ q38 +11.18pp > plus 0pp。崩溃模式最重的模型，容错救得最多。推论：**harness 健壮性投资的价值 = Σ(各模型档的崩溃模式损失)**，模型越多档、越杂，这类投资回报越高。

### 4.3 容错 ≠ 放弃校验：降级要降在正确的层

逐行容错把"整段报废"降级为"该行缺省沿用"——这是把失败**降级到语义上最接近正确的解释**（模型写 `state.rtt=state.rtt` 的意图就是沿用），而不是无脑吞异常。同类系统设计容错时，先问：这个异常的"最接近正确的降级语义"是什么？

### 4.4 写法规范与写法容错双管齐下

单用 prompt 约束 → 漏网坏写法仍崩；单用沙箱容错 → 冗余沿用行还在（占 token、增加噪声）。双管齐下后 v2 的继承类错误（CTX 4 例）基本清零。**对模型行为的改造，prompt（引导）和 harness（兜底）从来不是二选一。**

### 4.5 模型档差距的主轴会被 harness 重塑

旧配置时代 plus−32b ≈ 27pp，归因"能力差距"；同配置对照后实际差距 15.4pp——**差距里有 1/3~1/2 是 harness 对不同写法习惯的容忍度差异，不是模型能力**。跨模型比较结论（尤其"XX 模型不行"）必须先确认 harness 对各模型档同等友好。
